# Provenienz-Notiz

Das Muster des Blatt-Schlusses (Auftrag `auftrag-maschinen-audits.md` §2):
jedes geschlossene Blatt trägt am Ende eine Provenienz-Notiz — die Granit-Zeile,
die die Herkunft eines Schlusses als Daten festhält statt als Abgas. Der Dialog
ist Abgas; die Operator-Überstimmungen sind Daten.

## Die drei benannten Zeilen

Der Auftrag benennt genau drei Inhalt-Kategorien. Drei Zeilen je Blatt:

1. **Frage-Ursprung** — woher die Frage kam (welcher Auftrag, welcher Befund,
   welche Registerzeile). Der Anker, nicht die Paraphrase.
2. **Operator-Überstimmungen** — die Entscheidungen des Operators, die den
   Schluss tragen, als nummerierte Daten (nicht als Gesprächs-Wortlaut).
3. **Benannte verworfene Pfade** — die Wege, die gemessen und verworfen wurden,
   je mit Grund; ein verworfener Weg ist ein Ergebnis, kein Verschweigen.

## „Zehn Zeilen" ist eine Menge, keine Kategorie

Die „zehn Zeilen" des Auftrags sind dieselben drei Kategorien mit mehr
Instanzen (mehrere verworfene Pfade, mehrere Überstimmungen) — nie erfundene
Kategorien. Eine Zeile ohne gemessenen Inhalt trägt `pending` (0-Kanon), nie
einen erfabrizierten Eintrag.

## Die erste Instanz

`docs/concepts/das-eine-instrument.md` §5 trägt die erste reale Provenienz-Notiz:
der Ursprung einer Registerzeile, zwei Korrekturen an der Erinnerung, die
benannte verlorene Provenienz-Datenbank. Name = Implementation: das Muster
benennt, was dort bereits ruht — es erfindet kein Beispiel.

## Bindung

- Jedes geschlossene Blatt (befund/paper/survey) trägt die drei Zeilen am Ende.
- Eine Notiz ist ein Register-Eintrag, kein Kommentar; sie wird committet wie
  das Blatt selbst.
- Ohne gemessene Überstimmung trägt die zweite Zeile `pending` — die
  Selbstauskunft ist `pending`, bis die Abrechnung sie fällt.
