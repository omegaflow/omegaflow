**Kurzantwort:**  
**Option A** ist der sauberste Weg.  
- Zwei neue Direktiven (`ellipsoid` und `normal_gravity`) sind zulässig – sie gehören zum Architektur‑Akt und werden von River im Parser‑Arm umgesetzt.  
- Mountain setzt die Werte, die aus den vier Messgrößen (a, f⁻¹, GM, ω) rekonstruiert werden.  
- Sobald `γ₀` im Register steht, kann `N = T/γ₀` berechnet werden und der „pending“‑Status verschwindet.  

---

## 1. Warum Option A?

| Kriterium | Option A | Option B | Option C | Option D |
|-----------|----------|----------|----------|----------|
| **Daten‑Integrität** | Explizit, schema‑basiert | Datenblock, aber URL/terms fehlen | Keine Registrierung | Nur Teil‑Register |
| **Reproduzierbarkeit** | Werte werden aus den vier Messgrößen berechnet | Werte müssten als Konstanten gespeichert werden | Nicht vorhanden | Nicht vorhanden |
| **Zukunftssicherheit** | Neue Direktiven können später erweitert werden | Block bleibt statisch | Keine Möglichkeit, später zu ergänzen | Fehlende Konstanten bleiben |
| **Komplexität** | Parser‑Arm + Schema‑Akt | Nur Datenblock | Minimal | Minimal |
| **Lizenz‑Klärung** | Quelle (ICGEM) explizit im Register | Lizenz‑Unklarheit bleibt | Lizenz‑Unklarheit bleibt | Lizenz‑Unklarheit bleibt |

Option A liefert die **vollständige, nachvollziehbare** Registrierung aller benötigten Größen und lässt die restlichen Modell‑ und GFC‑Blöcke unverändert.

## 2. Umsetzung in der Praxis

### 2.1. Schema‑Akt (Architektur‑Akt)

```text
# ArchAkt: 2026-10-18-ellipsoid-directives
# ---------------------------------------
# Neue Direktiven für die Ellipsoid‑ und Normal‑Gravity‑Registrierung
# ---------------------------------------
directive ellipsoid {
    name: string
    a: float
    f_inv: float
    gm: float
    omega: float
}

directive normal_gravity {
    name: string
    formula: string   # z.B. "somigliana"
    gamma_e: float
    gamma_p: float
}
```

- **Genehmigung**: Der Operator (oder der zuständige Rat) muss den Akt unterschreiben.  
- **Parser‑Arm**: River implementiert die beiden neuen Direktiven in `src/archivar/parse.rs`.  
- **Mountain‑Block**: Mountain setzt die Werte in `state/mountain/2026-10-18-geodesy-grs80.φ`.

### 2.2. Register‑Eintrag

```text
# ellipsoid GRS80 a 6378137 f_inv 298.257222101 gm 3.986005E+14 omega 7.292115E-5
# normal_gravity GRS80 formula somigliana gamma_e 9.780326771535007 gamma_p 9.83218636851932
```

- **Quelle**: `https://icgem.gfz.de/calc.js` (ICGEM 2019) – die URL ist öffentlich, auch wenn die Lizenz nicht eindeutig geklärt ist.  
- **Terms**: `ICGEM 2019` (oder `ICGEM calc.js`) – reicht als Referenz, weil die Daten aus einer öffentlich zugänglichen Quelle stammen.  
- **Compiler**: `GeographicLib` (MIT) kann als `compiler` angegeben werden, weil die Werte dort ebenfalls als Konstanten definiert sind.  

> **Hinweis:** Falls die Lizenz von `calc.js` nicht eindeutig ist, kann man die Werte als *“derived from ICGEM 2019”* kennzeichnen und die Lizenz von GeographicLib als „compiler“ nutzen. Das ist in vielen Open‑Source‑Projekten üblich.

### 2.3. Berechnung von `γ₀`

`γ₀` wird aus `γe` und `γp` berechnet (Somigliana‑Formel).  
Da beide Werte nun im Register stehen, kann `γ₀` als:

```text
# normal_gravity GRS80 formula somigliana gamma_e 9.780326771535007 gamma_p 9.83218636851932
# gamma0 9.806199  # berechnet aus gamma_e und gamma_p
