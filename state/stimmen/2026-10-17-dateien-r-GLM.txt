## Verdikt

**Die Aufteilung ist im Prinzip richtig, im Bestand driftig.** Start trägt Kontext, Turn trägt Verhalten — das gilt heute schon fast. Aber es gibt **zwei Regel-Quellen für dasselbe Verhalten** (Datei 1 vs. Datei 3, Tools) und **zwei Configs, die sich widersprechen** (Datei 5 vs. 6, Modell + Shell). Die Turn-Belastung ist zu hoch: Datei 3 (SKILL) dupliziert Datei 4 (AGENTS) fast vollständig.

---

## F1 — Start vs. Turn

**Darf bei jedem Turn stehen (Verhalten, ohne das falsch gehandelt wird):**
- **Datei 1** (global AGENTS): Tool-Präferenzen sind Verhalten — jeder Bash-Turn braucht sie. ✅ korrekt platziert.
- **Datei 4** (omegaflow AGENTS): Axiom, Commit-Regeln, Feld-Syntax — Verhalten, das pro Turn gilt. ✅ korrekt platziert, und sie ist **die eine Regel-Quelle** des Projekts.

**Gehört zum Start (einmal, Kontext):**
- **Datei 3** (SKILL): Sie ist *Kontext* (Stack, Protokoll, Hardware, Council) — nicht Verhalten. Sie sagt es selbst: *"This skill provides quick context when AGENTS.md is not available."* Sie ist also **bewusst eine Kopie** — das ist Drift per Definition.
- **Datei 7** (Commands): Start der Linie, einmal. ✅ korrekt.

**Config-Dateien (2, 5, 6)** werden vom Laufzeit-System gelesen, nicht vom Modell — sie sind kein Regelbestand, sondern Apparat. Sie zählen nicht zur Regel-Frage, aber sie *verursachen* Risse (F2).

**Wie viele Regel-Dateien?** Zwei pro Turn (global + projekt-AGENTS), eine pro Start-Kontext (SKILL **oder** AGENTS — nicht beide), eine pro Linien-Start. **Eine Regel-Quelle: `omegaflow/AGENTS.md`.** Alles, was dort steht, steht nirgends sonst.

---

## F2 — Die Risse (wörtlich)

1. **Tool-Tabelle doppelt.** Datei 1: *"Für Inhaltssuche immer das integrierte Grep-Tool nutzen"* + `archive_search`-Fallback. Datei 3: *"Tools: `archive_search` (…) — run through the `bin/` wrappers"*. Zwei Quellen, ein Verhalten. Wenn sich die Wrapper-Regel ändert, driftet eine davon still.
2. **Axiom doppelt.** Datei 4: `A = A`, `0 honored`. Datei 3: *"Axiom: A = A. … (`0 honored` …)"*. Wörtlich dieselbe Regel an zwei Orten.
3. **Modell-Widerspruch.** Datei 5: `"model": "deepseek/deepseek-flash"`. Datei 6: `"model": "deepinfra/deepseek-ai/DeepSeek-V4.1-Flash"`. Zwei Configs, zwei Modelle, zwei Shells (`agent_sandbox` vs. `private_shell`) — niemand kann sagen, **welche gilt**. Das ist exakt der Anlass: *"niemand weiß, welche Datei beim Start wirklich gilt."*
4. **`small_model` vs. `small-model`.** Datei 5 schreibt `small_model`, Datei 6 schreibt `small-model`. Mindestens einer ist ein toter Schlüssel.
5. **Datei 3 ist eine tote Datei im Normalbetrieb.** Sie selbst sagt: nur relevant, *"when working from OTHER directories or when AGENTS.md is not available"*. Innerhalb des Projekts wird sie geladen und dupliziert nur. Sie ist der Grund, warum der Start-Prompt den Baum kämmt: sie verspricht Quick Context, aber verweist zugleich auf AGENTS.md — der Marker fehlt.
6. **`instructions: ["AGENTS.md"]` doppelt.** Datei 5 und 6 laden AGENTS.md explizit — und opencode lädt sie ohnehin automatisch. Harmlos, aber ein weiterer stiller Doppel-Pfad.
7. **Datei 2 (globale Config) ist fast leer an Regel.** Nur Modell + ein MCP-Server. Kein Riss, aber sie ist keine Regel-Quelle — sie darf nicht als solche behandelt werden.

## F3 — Der Bau

**Datei → Inhalt:**

| Datei | Wann | Trägt |
|---|---|---|
| `~/.config/opencode/AGENTS.md` | **jeder Turn** | Nur Tool-Präferenzen + Fallbacks (Datei 1, unverändert). **Nur hier** die Tool-Tabelle. |
| `omegaflow/AGENTS.md` | **jeder Turn** | Axiom, Feld-Syntax, Commit-Regeln, `bin/`-Wrapper-Regel (aus Datei 3 hierher, dort streichen). **Die eine Regel-Quelle.** |
| `omegaflow-personal/opencode.json` | Start (Apparat) | Modell, Shell, Agents — **einzige** Modell-Definition. Datei 5 streicht `model`/`small_model` oder Datei 6 wird gelöscht. |
| `~/.agents/skills/omegaflow-skill/SKILL.md` | **nur** Skill-Load von außen | Nur das, was in AGENTS.md **nicht** steht: Stack, Protokoll-Details, Hardware, Council. Erste Zeile: *"Wenn `omegaflow/AGENTS.md` existiert: nur diese lesen, dann stoppen."* — **das ist der fehlende Marker**, der den 150-Dateien-Kamm ersetzt. |
| `command/<linie>.md` | `/<linie>`-Start | Eine Rolle-Zeile, wie heute. Unangetastet. |

**Eine Regel:** Ein Verhalten steht an genau einem Ort. Der SKILL ist Ausnahme-Fallback, nicht zweite Quelle. Der 150-Dateien-Scan war kein Unfall — er war das Fehlen genau dieses einen Satzes.
